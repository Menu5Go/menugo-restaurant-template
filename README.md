# MenuGo – قالب المينيو الإلكتروني للمطاعم

هذا مشروع مستقل عن أي مشروع آخر. كل نسخة من هذا القالب مخصصة لمطعم واحد، مع مشروع Supabase مستقل لذلك المطعم.

## المتطلبات
- Node.js 20 أو أحدث
- حساب Supabase ومشروع مستقل للمطعم
- مستودع GitHub الخاص بالقالب

## التشغيل محلياً
1. فك ضغط الملف.
2. افتح مجلد المشروع.
3. نفّذ:
   ```bash
   npm install
   ```
4. انسخ `.env.example` إلى `.env` واملأ:
   - `VITE_SUPABASE_URL`: رابط مشروع Supabase.
   - `VITE_SUPABASE_ANON_KEY`: Publishable key فقط.
   - `VITE_OWNER_EMAIL`: بريد Google الوحيد المسموح له بإدارة المطعم.
5. نفّذ `001_initial_schema.sql` إذا لم تكن الجداول الأساسية موجودة بالفعل. لا تعِد تشغيله على قاعدة قائمة دون مراجعة.
6. نفّذ `002_visitor_analytics.sql` إذا لم تكن إضافات الإحصائيات مطبقة.
7. نفّذ `003_security_hardening.sql` لإعادة ضبط سياسات RLS الأساسية.
8. نفّذ `004_menugo_features.sql` لإضافة الحقول الثنائية والطلبات المرقمة والتقييمات الخاصة وStorage.
9. تحقق من Google OAuth وRedirect URLs. بريد المدير المثبت في `003` و`004` هو `afryst61@gmail.com`.
7. فعّل Google provider من Supabase Authentication واضبط Site URL وRedirect URLs للرابط المحلي ورابط الموقع المنشور.
8. شغّل:
   ```bash
   npm run dev
   ```
9. لفحص بناء الإنتاج:
   ```bash
   npm run build
   ```

## رفعه إلى GitHub
ارفع محتويات هذا المجلد إلى المستودع الخاص `menugo-restaurant-template`. لا ترفع ملف `.env` أو أي مفاتيح سرية. ملف `.env.example` آمن لأنه لا يحتوي أسراراً.

## المزايا الموجودة في هذه النسخة
- واجهة عربية RTL متجاوبة.
- قائمة أقسام ومنتجات مع بحث.
- سلة وكميات وملاحظات وإجمالي.
- زر واتساب قابل للتفعيل والإيقاف ورقم قابل للتعديل.
- تسجيل الطلب داخلياً إلى Supabase عند تفعيل الخيار.
- إعداد روابط فيسبوك وإنستغرام وإظهار/إخفاء كل رابط.
- لوحة إدارة لصاحب المطعم بعد تسجيل Google.
- إدارة الأقسام والمنتجات.
- إنشاء QR مع وسم الزيارات القادمة من الرمز وتنزيل PNG والطباعة.
- إحصائيات آخر 30 يوماً: الزوار الفريدون، الزيارات، زوار QR، مرات فتح QR، الزيارات المباشرة، ومشاهدات المنتجات، مع ملخص يومي لأسبوع وأعلى المنتجات مشاهدة.
- مخطط قاعدة بيانات وسياسات RLS كبداية.

## ما أضيف في هذه النسخة
- اختيار اللغة العربية أو الإنجليزية وحفظ الاختيار محلياً مع ضبط اتجاه الصفحة RTL/LTR.
- حقول أسماء وأوصاف المنتجات بالعربية والإنجليزية، وحقول أسماء الأقسام باللغتين.
- رفع صور المنتجات والشعار والغلاف إلى bucket باسم `menugo-assets` مع حد 5MB وأنواع JPG/PNG/WebP.
- واجهة طلبات المدير وتحديث حالات الطلبات.
- تقييمات نجوم وتعليقات اختيارية؛ القراءة والملخص محصوران بالمدير، مع حد تقييم واحد لكل منتج لكل معرّف متصفح.
- ترقيم الطلبات، وسياسة تمنع الإدخال الداخلي عندما يكون استقبال الطلبات متوقفاً.
- ملحق SQL `004_menugo_features.sql`.

## ملاحظات أمان
- لا تستخدم `service_role` أو `sb_secret` في الواجهة.
- لا تضع كلمة مرور Google في قاعدة البيانات.
- دالة `menugo_is_owner()` في migration 003 تستخدم البريد الثابت `afryst61@gmail.com` ومزود Google. Migration 004 يوحّد الدالة القديمة معها.
- الزائر الفريد يُحسب بمعرّف عشوائي محلي؛ حذف بيانات المتصفح أو استخدام جهاز آخر قد يؤدي إلى احتسابه كزائر جديد.
- لا تعتبر إخفاء زر في الواجهة حماية؛ RLS هو حاجز الصلاحيات الأساسي.
- إعداد OAuth يحتاج ضبطاً من لوحة Supabase وGoogle Cloud، ولا يمكن إتمامه من ملفات المشروع وحدها.


## دخول المدير (الرابط الخاص)
- رابط المدير المنشور: `https://menu5go.github.io/menugo-restaurant-template/?admin=1`
- لا يظهر رابط أو زر لوحة الإدارة في شريط الموقع للزوار.
- Google OAuth يعيد المستخدم إلى مسار GitHub Pages الصحيح مع `?admin=1`.
- تظهر لوحة الإدارة فقط إذا كان البريد `afryst61@gmail.com` مؤكداً ومصدر تسجيل الدخول Google.
- هذا الرابط ليس كلمة مرور؛ الحماية الفعلية تعتمد على التحقق من الجلسة وسياسات RLS.

## ترقية سياسات RLS
يتضمن المشروع `003_security_hardening.sql` لإعادة ضبط سياسات الجداول الأساسية، ثم `004_menugo_features.sql` لإضافة الجداول والسياسات الجديدة. الملف 003 يستبدل كل السياسات على الجداول التالية:
`restaurant_settings`, `categories`, `products`, `orders`, `analytics_events`.
راجع أسماء الجداول والأعمدة في مشروع Supabase أولاً، ثم نفّذ الملف من SQL Editor.
**تنبيه:** هذا الملف يستبدل كل السياسات الحالية على هذه الجداول. كما يجب فحص صلاحيات دالة RPC المسماة `get_menu_analytics` الموجودة في migration الإحصائيات؛ لا يمكن تأكيد أمانها دون مراجعة تعريفها الحالي. لا تمنح `service_role` للواجهة مطلقاً.


## إعداد GitHub Actions
يستخدم workflow الحالي أسرار GitHub المسماة `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ويحوّلها إلى متغيرات Vite وقت البناء. إذا كانت أسرارك الحالية تحمل أسماء أخرى، عدّل أسماء المراجع في `.github/workflows/main.yml` لتطابقها؛ لا تضع service_role أو secret key في أسرار الواجهة.

## حدود التحقق
لا يمكن اختبار OAuth الفعلي أو سياسات RLS أو Storage أو إرسال الطلبات على مشروع Supabase الحي من ملف ZIP وحده. بعد تشغيل migrations، اختبر بحساب المدير وبجلسة زائر، ثم اختبر الموقع المنشور. تقييمات الزوار تعتمد على معرّف عشوائي في المتصفح ويمكن تجاوزها بمسح التخزين أو تغيير الجهاز؛ لا تعتبرها آلية هوية موثقة.

## ملاحظة عن الترجمة
تمت إضافة حفظ اللغة والاتجاه ومحتوى الأقسام والمنتجات باللغتين، مع ترجمة أجزاء من واجهة الزائر. ما زالت بعض تسميات لوحة الإدارة والنصوص الثابتة عربية؛ يلزم استكمال قاموس ترجمة شامل قبل اعتبار شرط ترجمة جميع عناصر لوحة الإدارة مستوفى بالكامل.


## إصلاح QR في هذه النسخة
يُبنى الرابط الافتراضي من `BASE_URL` الخاص بـ Vite ومصدر الصفحة. في GitHub Pages يجب أن يكون:
`https://menu5go.github.io/menugo-restaurant-template/?source=qr`
ويمكن تحديد `VITE_PUBLIC_MENU_URL` إذا رغبت في تجاوز الرابط الافتراضي.

## حدود النسخة المحدثة
راجع `IMPLEMENTATION_STATUS.md` قبل النشر. هذه الجولة أصلحت رابط QR الافتراضي وحسّنت تعريب بيانات الإحصائيات، لكنها لا تدّعي اكتمال ترجمة لوحة الإدارة أو نجاح بناء Vite أو اختبار Supabase الحي؛ هذه العناصر تحتاج تثبيت dependencies/وصولاً إلى الخدمات الفعلية.
