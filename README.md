# MenuGo – قالب المينيو الإلكتروني للمطاعم

هذا مشروع مستقل عن أي مشروع آخر. كل نسخة من هذا القالب مخصصة لمطعم واحد، مع مشروع Supabase مستقل لذلك المطعم.

## المتطلبات
- Node.js 20 أو أحدث
- حساب Supabase ومشروع مستقل للمطعم
- مستودع GitHub الخاص بالقالب

## التشغيل محلياً
1. فك ضغط الملف.
2. افتح مجلد المشروع.
3. نفّذ:
   ```bash
   npm install
   ```
4. انسخ `.env.example` إلى `.env` واملأ:
   - `VITE_SUPABASE_URL`: رابط مشروع Supabase.
   - `VITE_SUPABASE_ANON_KEY`: Publishable key فقط.
   - `VITE_OWNER_EMAIL`: بريد Google الوحيد المسموح له بإدارة المطعم.
5. نفّذ ملف `001_initial_schema.sql` في SQL Editor بمشروع المطعم بعد استبدال `owner@example.com` بالبريد نفسه.
6. بعده نفّذ ملف `002_visitor_analytics.sql` لتفعيل إحصائيات الزوار ومصدر QR.
7. فعّل Google provider من Supabase Authentication واضبط Site URL وRedirect URLs للرابط المحلي ورابط الموقع المنشور.
8. شغّل:
   ```bash
   npm run dev
   ```
9. لفحص بناء الإنتاج:
   ```bash
   npm run build
   ```

## رفعه إلى GitHub
ارفع محتويات هذا المجلد إلى المستودع الخاص `menugo-restaurant-template`. لا ترفع ملف `.env` أو أي مفاتيح سرية. ملف `.env.example` آمن لأنه لا يحتوي أسراراً.

## المزايا الموجودة في هذه النسخة
- واجهة عربية RTL متجاوبة.
- قائمة أقسام ومنتجات مع بحث.
- سلة وكميات وملاحظات وإجمالي.
- زر واتساب قابل للتفعيل والإيقاف ورقم قابل للتعديل.
- تسجيل الطلب داخلياً إلى Supabase عند تفعيل الخيار.
- إعداد روابط فيسبوك وإنستغرام وإظهار/إخفاء كل رابط.
- لوحة إدارة لصاحب المطعم بعد تسجيل Google.
- إدارة الأقسام والمنتجات.
- إنشاء QR مع وسم الزيارات القادمة من الرمز وتنزيل PNG والطباعة.
- إحصائيات آخر 30 يوماً: الزوار الفريدون، الزيارات، زوار QR، مرات فتح QR، الزيارات المباشرة، ومشاهدات المنتجات، مع ملخص يومي لأسبوع وأعلى المنتجات مشاهدة.
- مخطط قاعدة بيانات وسياسات RLS كبداية.

## نقاط يجب إكمالها قبل البيع/الإطلاق
- مراجعة سياسات RLS واختبارها بحساب المالك وزائر غير مسجل.
- إضافة إدارة حالات الطلبات وواجهة عرض الطلبات في لوحة الإدارة.
- رفع صور المنتجات إلى Supabase Storage بدلاً من الاكتفاء بروابط الصور.
- إضافة تصدير QR إلى PDF وتصميم حامل طاولة.
- اختبار دقة الإحصائيات وسياسات RLS على مشروع Supabase فعلي قبل الإطلاق.
- إضافة إدارة الترجمات الفعلية (العربية/الإنجليزية/التركية).
- تنفيذ اختبارات كاملة على مشروع Supabase فعلي ونطاق منشور.

## ملاحظات أمان
- لا تستخدم `service_role` أو `sb_secret` في الواجهة.
- لا تضع كلمة مرور Google في قاعدة البيانات.
- غيّر البريد داخل دالة `is_restaurant_owner()` في migration 001 قبل تشغيل SQL، ثم نفّذ migration 002.
- الزائر الفريد يُحسب بمعرّف عشوائي محلي؛ حذف بيانات المتصفح أو استخدام جهاز آخر قد يؤدي إلى احتسابه كزائر جديد.
- لا تعتبر إخفاء زر في الواجهة حماية؛ RLS هو حاجز الصلاحيات الأساسي.
- إعداد OAuth يحتاج ضبطاً من لوحة Supabase وGoogle Cloud، ولا يمكن إتمامه من ملفات المشروع وحدها.
