MenuGo – الدفعة الثانية: أرشفة المبيعات والحذف الآمن بعد 4 أشهر

النسخة الأساسية: MenuGo-v18-Batch1.zip (آخر نسخة تم تسليمها في الدفعة الأولى).

التغيير البرمجي في هذه الدفعة:
- إضافة ملف SQL واحد فقط: 012_order_retention_and_sales_archive.sql
- لم يتم تعديل App.jsx أو styles.css أو وظائف الواجهة.

ما يفعله ملف SQL:
1) ينشئ سجلاً مالياً مستقلاً لكل طلب مؤرشف، مع الاحتفاظ بمعرّف الطلب ورقمه الأصلي وتاريخ إنشائه ويوم العمل والإجمالي والحالة النهائية.
2) ينشئ ملخصات مبيعات يومية وشهرية كاملة من الأرشيف والطلبات التي ما زالت محفوظة في orders.
3) الطلبات الملغاة تدخل في عدد الطلبات، ولا تدخل في الإيرادات، موافقةً لمنطق إيرادات لوحة التحكم الحالية.
4) لا يختار للحذف إلا الطلبات الأقدم من 4 أشهر وحالتها completed أو cancelled.
5) لا يحذف الحالات new أو reviewing أو accepted أو preparing أو ready.
6) ينفذ الأرشفة والحذف في معاملة واحدة؛ إذا فشلت العملية يتم التراجع عن تغييرات الأرشفة والحذف وتسجيل الفشل.
7) يسجل كل تشغيل في menugo_order_retention_runs.
8) يضيف مهمة pg_cron تعمل كل ساعة، وبحد أقصى 500 طلب في كل تشغيل.
9) يوفر RPC باسم menugo_get_sales_history_summary للمالك لقراءة الإجماليات والملخصات اليومية والشهرية.

طريقة التطبيق:
- خذ نسخة احتياطية من مشروع Supabase أولاً.
- افتح SQL Editor في مشروع المطعم نفسه.
- تأكد أن migrations من 001 إلى 011 مطبقة بنجاح.
- تأكد من تفعيل Supabase Cron / pg_cron (سيحاول ملف SQL تفعيله أيضاً).
- شغّل محتوى 012_order_retention_and_sales_archive.sql مرة واحدة.
- راجع نتيجة التنفيذ وسجلّات التشغيل وجدول cron قبل اعتبار الجدولة مفعلة.

استعلامات مراجعة بعد التطبيق:

-- آخر عمليات الأرشفة والحذف:
select * from public.menugo_order_retention_runs order by started_at desc limit 20;

-- ملخص المبيعات اليومية (الأرشيف + الطلبات التي لم تُحذف بعد):
select * from public.menugo_sales_history_daily order by business_date desc limit 60;

-- ملخص المبيعات الشهرية:
select * from public.menugo_sales_history_monthly order by month_start desc limit 24;

-- التأكد من وجود المهمة:
select jobid, jobname, schedule, active
from cron.job
where jobname = 'menugo-order-retention-hourly';

ملاحظات وحدود مهمة:
- يحتفظ الأرشيف بالبيانات المالية التاريخية الأساسية فقط، ولا يحتفظ بملاحظات الزبون أو visitor_id أو تفاصيل الأصناف JSON أو بيانات الطاولة؛ هذه التفاصيل تُحذف مع الطلب الأصلي.
- لا توجد في المخطط الحالي جداول مستقلة لتفاصيل الطلبات؛ الأصناف مخزنة داخل orders.items بصيغة JSONB.
- يعتمد التنفيذ على Supabase Cron / pg_cron. إذا تعذر تفعيل الامتداد أو لم تظهر المهمة في cron.job، فلا تعتبر الحذف التلقائي مفعلاً.
- كل نسخة MenuGo تعمل في مشروع Supabase مستقل؛ الدالة لا تستهدف إلا public.orders وجداول الأرشيف داخل المشروع الذي طُبّق عليه الملف.
- لم يتم الاتصال بمشروع Supabase أو تنفيذ SQL عليه من هذه الجلسة، لذلك لم يتم التحقق المباشر من نجاح التطبيق أو تشغيل cron فعلياً.
